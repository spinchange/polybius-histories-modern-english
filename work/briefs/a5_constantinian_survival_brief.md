## Entry shape
Same schema as part 1: `id: survival/<BB>-<C>` (or `survival/<BB>-<C1>-<C2>` for a run; the
validator requires id to equal `survival/<filename stem>`), `layer: survival`, anchor list,
`annotator`/`work` naming the collection and witness, `date` (Constantine's collections c. 950;
state a date only if you are sure), `tags: [survival-story]`, `pd_basis: none`,
`status: verified`. Body is `**Note:**` only, four sentences or fewer. Say which collection or
codex preserved the chapter, cite the apparatus note it rests on in plain words, and say so if
confidence is only medium. Do not quote the Greek in the entry.

Extend the generator rather than hand-writing 38 files: add a data file such as
`work/survival_witnesses.csv` (book, chapter, collection, witness, evidence, confidence) and have
`ann_survival_gen.py` read it, so the files stay reproducible and `--force` never destroys
hand-edited entries (it only touches files carrying `generated:`; keep it that way).
